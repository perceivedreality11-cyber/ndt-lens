# 项目讲解与简历素材

下面的表述对应仓库实现，可按本人实际工作与岗位要求调整。

## 项目名称与简介

**NDT Lens｜基于 YOLO 的工业射线缺陷检测与协同标注系统**

技术栈：Python、PyTorch / Ultralytics YOLO11、OpenCV、Streamlit、SQLite、Canvas、pytest、GitHub Actions。

## 简历描述示例

- 实现工业射线图像的“人工标注—模型训练—自动标注—人工复核”闭环，支持气孔、裂纹、夹杂三类缺陷检测与本地批量处理。
- 构建基于像素 SHA-256 的图片去重、工件分组隔离、标注版本校验和确认样本训练快照，降低数据泄漏及未复核预测污染训练集的风险。
- 封装 YOLO 训练/推理与后台任务状态，提供独立 test 评估、固定阈值检测指标及可搬移的 YOLO 数据集导出；通过自动化测试与跨平台 CI 验证核心流程。

不建议把合成图指标写成工业现场准确率。若之后完成真实数据实验，可补充“数据来源、工件组数、独立测试集、每类 Recall、mAP、推理设备与耗时”，再将对应结果加入简历。

## 90 秒介绍

“这个项目针对工业射线缺陷检测中的标注和模型迭代流程。我把图片导入、人工框选、深度学习训练、后续图片自动标注和复核放在一个本地工作台中。难点除了接入 YOLO，还包括如何保证下一轮训练使用可靠数据：我按工件组隔离 train/val/test，保存前校验标注版本，只把确认过的样本复制到独立训练快照。模型的输出始终待复核，不能自动变成真值。训练放在独立进程中，切换页面不会打断，并保存参数、环境和日志。项目附有传统方法与 YOLO 的合成数据对比实验；真实工业泛化仍需有授权的数据验证。”

## 可以深入讲的设计点

| 面试问题 | 结合代码回答 |
|---|---|
| 为什么不用自动预测直接训练？ | 错误预测可能被下一轮模型重复学习。`reviewed` 是进入快照的条件，零预测框也需确认。 |
| 怎样避免泄漏？ | 导入时限制组号跨集合，并检查相同像素；同一原始底片切片前先分组。哈希不能识别所有近似图。 |
| 标签在训练中被修改怎么办？ | 训练使用复制后的快照；交互标注使用 `revision` 乐观更新。 |
| 模型无框是否说明正常？ | 不能。数据库区分“未确认的空预测”和“确认的正常样本”。 |
| 怎样比较算法？ | 同一 held-out test 集、同一 IoU 下比较固定阈值 P/R/F1；YOLO 另报告官方 mAP，说明两种指标定义不同。 |
| 为什么保留传统方法？ | 无模型时可以演示候选定位，也作为可解释的基线，暴露深度学习在小数据和小目标上的失败。 |
| 如何处理高位深图？ | 一致的百分位窗转换并保留原始字节；说明其丢失绝对强度的限制。 |
| 假如同时开两个页面？ | `UPDATE ... WHERE revision=?` 拒绝旧版本覆盖；当前仍是单用户工作台，不声称团队协作系统。 |
| 如何证明不是界面原型？ | 展示可运行脚本、后台训练权重产物、独立评估 JSON、导出往返测试和 CI 结果。 |

## 现场演示顺序

1. 打开项目并点击“打开合成演示项目”，解释生成数据和预置真值的来源。
2. 选择缺陷图，画框、修改表格并保存；展示草稿与确认的区别。
3. 在训练中心用离线配置跑 1 轮，展示任务记录及结果。
4. 选择刚训练的模型，对 3 张待标注图执行推理。说明短训练可能无框；展示待复核状态与来源记录。
5. 导出已确认数据，解压后执行 `ndt check-data`；再展示正式合成实验的参数与结果。

## 下一步可以形成真实成果的工作

1. 获取可合法使用的真实射线数据，记录工件/底片分组、缺陷类别与标注一致性。
2. 与传统基线和通用预训练模型做对比，在独立真实 test 集统计每类漏检。
3. 对小缺陷做分辨率、切片与增强消融实验，记录训练开销和推理耗时。
4. 研究基于不确定性的待标注样本排序，衡量固定标注预算下的性能变化。

这些是后续实验方向，不能作为当前已经完成的成果。
