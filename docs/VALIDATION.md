## 自动化配置与本地验证的区别

GitHub Actions 配置 Windows / Linux × Python 3.10 / 3.12，执行格式、静态检查、测试、CLI 演示和 wheel 构建。配置不等同于已通过，实际结果以仓库 Actions 为准。

默认 CI 不安装训练依赖，不下载模型，不进行训练；真实 YOLO 训练通过单独的本地实验验证。

本机没有完成真实工业数据训练或 CUDA 验证。当前测试环境复用了已安装依赖，干净环境的安装结果由 CI 验证。浏览器交互与线上 CI 的最终结果会随发布过程补充。

## 浏览器与独立进程补充验证

一键合成演示入口正常打开；实际加载 100 轮合成模型，对 3 张待标注图执行批量预测并读取 SQLite 确认模型来源和待复核状态，12 张已确认标注未改变。另在新项目独立 Python 环境中启动 1 轮后台训练，成功生成 best.pt、environment.json 和完成状态。

当前推理坐标裁剪逻辑重新评估 18 张合成 test 图，与已归档固定阈值指标一致。真实工业数据与 CUDA 仍未验证。

## CI 首轮发现并修复的问题

首轮 GitHub Actions 的功能测试通过，但 Windows 的 `demo-workspace` 命令受默认代码页影响，无法输出中文；Python 3.12 的 wheel 命令因禁用构建隔离而无法找到 setuptools 后端。分别通过 CLI 显式 UTF-8 输出及恢复 PEP 517 构建隔离修复，并增加旧终端编码回归测试。修复后的线上结果以最新 Actions 记录为准。
